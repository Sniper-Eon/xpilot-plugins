# 手机定位优先（Android v24）

内置高德 SDK 的实时导航采用以下顺序：

1. 手机定位新鲜且质量合格时，优先用手机。
2. 手机定位缺失、过期、弱信号或质量不合格时，才允许采用合格的车端备用定位。
3. 两端均无合格数据时，保持定位不可用，不生成坐标，不延长旧数据寿命。

“车端备用”是程序预留的遥测输入，并不代表每辆 Tesla 的 CAN 都有可用定位。
用户已明确当前车辆没有该定位 CAN 数据，不能宣称本车备用通路已可用。
高德车机版是另一个导航来源，与这里的定位来源不是同一概念。

时效沿用原来的严格 3 秒边界，精度、速度、航向、坐标系和测量时间检查保持原值。
车辆重复样本不重复注入，时间倒退/停止/SDK 异常仍按原规则失效。
从车端备用切回手机时，关闭 SDK 外部定位输入，并清掉旧外部样本；车端注入后
由 SDK 回显的位置不能被当成手机恢复。独立 Android GPS 监听确认的真实恢复
可触发交回手机，即使 SDK 的卫星弱信号回调暂未更新；导航控制仍须等待新的
SDK 定位和路线匹配，既有来源就绪检查不变。

手机 GPS、完整路线和推荐车道能提供道路位置及导航依据，不能直接给出当前
自车车道编号。SDK 11.2.100 公开的 AMapLaneInfo 提供车道方向/总数/推荐，
AMapNaviLocation 提供坐标、精度及道路匹配，没有自车绝对车道号。
路线几何当前仍为观察数据；本次不改 C3 的选道、盲区、实线或执行开关。

v24 同时加入玻璃面板质感 X 图标，使用 Android 原生矢量/自适应图标，保留原
包名、签名和应用名称。覆盖安装不会创建新的应用分身。道路效果需要实际验证。

## v25 待设备验证候选：独立手机 GNSS 输入

v24 的优先级修改没有补齐“SDK 持续弱信号、原车没有 GPS CAN”的冷启动路径。
v25 候选优先选择合格的独立 Android GPS 观测，通过高德原有外部定位接口
送入真实手机坐标，GPS 坐标类型为 1。独立 GPS 的经纬度、精度、速度、航向及
真实测量时间须齐全；非模拟、WGS-84、未过期及原有质量条件全部保留。
重复观测不重复注入，时间倒退或过期即失效。SDK 根据输入返回的坐标不作为
独立 GPS 再参与选源；数据源或输入模式变化时，必须重新取得新鲜的路线匹配。

这不是强制清除弱信号标记，也不是制造新的定位时间。SDK 弱标记仅在另有
合格的真实手机输入时不再决定该输入是否可用；路线/源就绪/控制检查仍须通过。
停止、模拟导航及 SDK 注入失败都会停止或拒绝这条输入。该候选未部署、未路测，
也不新增绝对车道号或改动 C3 选道与信号控制逻辑。
