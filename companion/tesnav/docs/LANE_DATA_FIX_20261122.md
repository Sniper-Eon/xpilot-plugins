# 车道数据缺失修复记录（2026-11-22）

本轮完成本地修复、检查和候选构建；未安装 v68，未替换或重启 C3，未进行路试。手机当前仍为前轮已安装的 v67；C3 主机 a0c4486247、导航插件 2.4.5-final。本记录不代表腾讯车道级驾驶已完成。

## 修复内容

1. 道路总数记忆：保留原 1 秒稳定确认，新增 90 秒最大证据年龄。只有合格车道回调刷新证据，循环和心跳不能续期。会话、路线或明确道路名称变化及插件关闭立即撤销；候选中断后重新计时。单独 Link 变化不当成换路。换路以后，旧道路回调时间早于切换边界的车道事实不能重新确认。
2. 数量过期后，保留本路旧布局作为拒绝未来拓宽数量的参考，不把它继续发布为有效总数。同一路段仍有方向机动时，不因旧值过期便重新接纳另一套未来数量。换道路后重新确认。
3. 准确运行备份候选：在融合之前维护总数；未确认当前总数时不直接用前方路口数量补齐融合；尊重滤波器 valid=False，旧后验不能继续以高置信度提交；显示链路不沿用失效总数。
4. 手机广播导出使用 lanesObservedAtMs，即 driveWay 自身回调时间；显示投影与原始广播共用这一观测时间。保留路径匹配和重算隔离，拒绝缺失、未来或超过 10 秒的车道事实。重复引导或导出不更新车道时间。
5. SDK 回调若早于首次 keyed guidance，记录该回调时已安装且匹配 acceptedPathId 的引擎路径；等同一条路径得到 guidance 确认才允许导出。冲突引擎、冲突路径或重算中不绑定。该顺序问题已离线复现修正，但没有证据证明它是报告当晚 0% 的唯一原因。日志新增 accepted/guidance/engine 路径字段用于后续定位。
6. 手机保留旧号时显示“布局待确认”，总数失效时显示“总数未知”；待确认号或数量不匹配的旧号不高亮前方车道箭头。

左右前方导航打灯变道没有取消。只读检查时导航、导航变道、物理打灯三个开关均为 1，车机代码仍包含 slightLeft/slightRight 路径。本轮没有改规划、打灯或变道执行规则；process.py 仅调整显示回传数量和待确认原因，也没有改 250/800/640/400 米门槛。开关与代码存在不等于已验证实际动作成功。

90 秒是本轮选用的缓存上限，不是高德有效期或已通过路试的最佳参数。是否属于当前道路仍依赖原运行版布局判断；本轮不宣称已经解决所有道路拓宽映射，也没有获得地面真值。
